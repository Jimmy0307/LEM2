03 · COMPUTATIONAL MECHANISM

瓶頸多發生於支持集型決策計分，而非全部來自 Reduct

你提供的原報告指出，已完成且 Wall Time 超過 60 秒的模型中，Predict 耗時占 91.9%、LEM2 占 5.1%、Reduct 只有 0.9%。這是以原分析匯總的階段計時為依據；兩份 per-source CSV 並未保存逐模型 Phase Timings，因此這裡不宣稱已獨立重算每個比例，更不能直接證明每個逾時模型最後停在哪一行。

核心成本：U × R × Ndev

U＝不同 Rule-Match Boolean Pattern 的數量；R＝規則數；Ndev＝Dev（真正訓練）列數，約為來源 64%。三種支持集計分策略的密集計算主項可用這個量級理解。

何時近似 n² × R？

只有在 U 接近 Test Rows（約 0.2n），Dev 約 0.64n 時，推論主項才可能呈平方量級；若規則集合有限、匹配樣式大量重複，U 遠小於 Test Rows，成本就可能遠低於平方。

為何一個慢策略拖垮 12 筆成績？

同一 dataset × seed × scenario 的模型會使用 A/B2 兩個 Rule Variants × 六種決策策略。原本程式需整組成功才能返回成績；若其中一個支持集策略逾時，先算完的策略也不能形成完整模型紀錄。

工程與方法學切割：Exact Reduct 的組合搜尋有潛在指數複雜度，但這批已完成的慢模型，從匯總結果看主要瓶頸是另一個階段。不能以「推論階段約 92%」推論 Rough Set 的 NP-hard 問題已解決，也不能把六種策略的後處理成本誤寫成 LEM2 規則歸納成本。

05 · ENGINEERING DECISION & STUDY LIMITATIONS

下一步：不宜只拉長 timeout

優先完成可成功的來源

adult_income、openml_42734 等 CI 五筆中多數成功的來源，值得先補完整；openml_41027、openml_42732 已有反覆 timeout 證據，應獨立記錄資源風險。

把缺漏當成研究限制

剩九個來源並非隨機遺失，尤其大型且高規則數的模型更容易失敗。不可用 179 個成功資料集推論到全部 188 個，也不能把 TIMEOUT 填成 Accuracy=0。

新的效能實驗需要版本隔離

下一版可對各決策策略單獨計時／checkpoint，研究 bitset／sparse support 與規則支持度索引，檢驗預測一致性（parity）。但不能替換既有 Frozen 42-seed Test 主結果。

研究定位：本輪量測的是固定特徵上限與 64/16/20 切分下的規則學習及後處理效能。沒有實驗證明 80/20 最佳、六特徵最佳、Client=3 最佳、或完整高維資料的運算效能。圖表不能單獨宣稱 `n²×rules` 是所有來源普適的時間定律。
