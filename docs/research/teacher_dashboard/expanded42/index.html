03 · EXTENDED COVERAGE / CONFLICT EVIDENCE

為什麼有規則命中，卻不一定能做出正確決策？

對於每一個資料集，在固定 42 個 Seed、同一分布與規則版本 下，先量測整個 Test Set 中的規則命中、正確決策是否在候選集合、無命中比例，以及同一物件被不同類別規則命中的衝突。這四個層級不能互相代替。

① Test Coverage

Covered / Test × 100%

測試資料中，至少一條規則的前件條件成立的比例；只代表有命中，不代表類別正確。

② Candidate Coverage

True-in-Candidates / Test × 100%

測試樣本真實類別是否包含在命中規則的候選決策集合中；這是事後評估指標，部署時不會知道真實類別。

③ No Match

No-Match / Test × 100% = 100 − Coverage

沒有任何規則前件成立的比例；即使最終分類器有 fallback 猜出類別，也不能把它算成被規則覆蓋。

④ Conflict Rate

Multi-decision matches / Test × 100%

同一筆資料同時匹配到不同決策類別的規則；命中多條但都指向相同類別，不算這個定義的衝突。

⑤ Covered but true class absent

Coverage − Candidate Coverage (pp)

有規則匹配，卻沒有任何候選決策包含真實類別。這是規則命中但無法從既有候選類別選對答案的直接證據。

⑥ 規則數／平均筆數

Mean over available Seeds

記錄平均 Test、Covered、No-Match、True-in-Candidates 筆數及 Rule Count；絕對筆數與百分比必須分開呈現，不能用百分比下降推論計算資源降低。

交集不可直接相減：Conflict 可能與「正確類別在候選集合內」同時發生；Conflict 不是分類錯誤率。上列數值都是逐 Seed 計算比例後平均；平均筆數也是逐 Seed 平均。Coverage−Candidate Coverage 可以解釋為比例差，但不要把全部百分比加成 100%。

代表性案例：需要辨別兩種不同問題

MNIST：規則幾乎無法覆蓋

784 → 6 Features，70,000 Rows。A 版四情境 Test Coverage 都是 0%，No Match 全部 100%；最高 Accuracy 約 11.25%，Balanced Accuracy 為 10%。這個案例提示「六特徵可能不足以留下有效的區辨資訊」，但沒有全特徵消融前，不能認定唯一原因。

Iris：覆蓋高卻高衝突

原始 4 → 使用 4 Features，因此不涉及六特徵截斷。在 α=0.1 的 A 版，Coverage 100%、Candidate Coverage 97.78%，但 Conflict 74.76%；B2 的 Conflict 約下降 52.62 pp。顯示高衝突不必然來自高維截斷。

AI4I：有候選也未必容易選答案

原始 6 → 使用 6 Features。α=0.1 的 A 版 Coverage 99.86%、Candidate Coverage 95.15%、Conflict 55.87%。B2 將衝突降低約 38.20 pp，但 Candidate Coverage 也下降 9.12 pp。

Bioresponse：極端高維截斷案例

1,776 → 6 Features。Centralized Coverage 只有 2.09%；α=0.1 時 Coverage 升至 95.92%，但 Candidate Coverage 為 67.55%，Conflict 為 36.96%。不能把「有規則命中」解讀成「有效分類」或宣稱已驗證完整 1,776 維模型。

Bank Marketing：高 Accuracy 也可能偏向多數類

原始 16 → 使用 6 Features；α=0.1 A 版 Coverage 94.97%、Candidate 78.84%、Conflict 55.80%，事後最佳 Accuracy 約 70.02%，但 Balanced Accuracy 約 50.32%。類別不平衡使單看 Accuracy 有誤導風險。

Banana：只用 2 Features 也會轉變

原始 2 → 使用 2 Features，Centralized Coverage 僅 0.38%；α=0.1 A 版 Coverage 95.11%、Candidate 76.31%、Conflict 56.29%。這是「所有非單調性皆由截成六維造成」的直接反例。

風險樣本盤點：高 Coverage 不等於高有效性

以自訂的描述性篩選門檻找出「Coverage ≥80% 且 Conflict ≥50%」、「有規則命中卻不包含正確類別 ≥20 pp」、「No Match ≥50%」的資料集。門檻是閱讀輔助，不是已證明的自然臨界值。

06 · METHODS / LIMITATIONS

給教授的研究定位與下一步

這一輪跑了什麼

每個資料集採用最多六個預先固定的候選特徵；同一份資料先進行 64／16／20 Development／Validation／Test 分割，Development 依 IID 或 Dirichlet label skew 分配給三個 Client。各 Client 使用相同特徵集合與相同 Target，局部尋找精確最小 Reduct、歸納 LEM2 規則，再合併去重。

下一輪不直接混入主結果

原始 Features >6 的 162 筆，後續才執行 `k=8/12/ALL` 或受資源約束的特徵選擇消融，另測 Client 數／跨 Client 特徵異質性。重新訓練必須固定 Test 分割及資源預算，並將結果保留在獨立實驗版本，不能覆蓋這一輪六特徵基準。

六特徵怎麼選：PMLB 與 OpenML 主要排除識別欄後依原始欄位順序選前六項；大部分 UCI 依來源順序取前六項，少數八筆事先設定業務／避免標籤洩漏的欄位。這不是資料驅動的最優六特徵。三個 Client 各自擁有最多六個相同 Features，不是把六特徵平均切成三份。

本輪研究限制：資料來源同源家族依賴、六特徵上限、HFL 相同 Schema／Target、四情境中的三客戶端模擬與 label-skew fallback、尚有九個資料集未完成、不同資料量的 CPU／時間複雜度、以及沒有執行完整 Feature Budget × Client Count 的消融。
