研究口徑與不可混用的限制

為什麼是109+51，而不是161份全部重新測試？

原始歷史清冊是161筆來源，其中PMLB候選117份、成功109份。51份OpenML是新的10 Seeds確認性研究，與歷史來源可能同源（包括ada、gina），因此不能宣稱已對160個獨立資料集完成同協定驗證。其餘歷史來源仍可在清冊查找，但不冒填不存在的成本或準確度。

Accuracy、Balanced Accuracy、Macro-F1各自回答什麼？

Accuracy是Test正確筆數除以Test總筆數；Balanced Accuracy為各類別Recall平均；Macro-F1為各類別F1平均。類別不平衡時應同時檢視三者。所有百分比顯示時才乘100，原始CSV保留0–1比例。

成本如何測量？

OpenML的通訊量是離散化階段估算的傳輸「數值個數／Client」，不是實際網路封包、加密成本或Server合併CPU。G5最大值是此來源10 Seeds內的觀測上限；非普適保證。PMLB只有模型擬合秒數，沒有相同口徑的通訊成本。兩批的秒數也不能直接跨環境比較。

Coverage / Conflict能否當作模型精確度？

不能。Coverage代表命中規則的比例；Conflict代表候選類別衝突。OpenML顯示Test Conflict與排除TRUE退化命中的Coverage代理值；PMLB的Conflict是Validation，Coverage是Test。較低Conflict可能伴隨較低有效Coverage；不能據此宣稱整體泛化比較好。

是否已找到最佳Server-side規則整合成本級距？

還沒有。本頁評估既有離散化與規則決策方法的成本—品質關係，沒有實測新的Server-only規則選擇器。新的規則數25%/50%/75%/100%成本掃描及真實通訊協定仍屬下一階段，不能寫成已完成。
