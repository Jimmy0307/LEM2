PROFESSOR REPORT · PREDICTION & METRIC CONTRACT

沒有 Conflict 時怎麼選？
有 Conflict 或平票又怎麼選？

一句話：六種方法是最後的分類選擇策略，不是產生或消除 Conflict 的方法。所有測試資料都會得到最終分類；只有多種候選決策時，六種方法才可能對同一筆資料產生不同答案。本頁解釋實際程式的規則，不把示意算例冒充真實實驗。

三種狀態 · 平票互動實例 · 指標與分母 · 程式證據

01 · MATCH BEFORE RESOLUTION

先取得所有命中規則，再判斷是否有多種候選決策

對每筆測試資料 x，先從固定的一份規則集合取出所有符合條件的規則 M(x)，再取其提出的不同決策集合 Cand(x)。

M(x) = {r ∈ R : r 的全部前件成立}；Cand(x) = {decision(r) : r ∈ M(x)}；Conflict(x) ⇔ |Cand(x)| > 1
A · NO MATCH

命中規則數 = 0

沒有候選類別，六種分類策略都使用訓練資料的多數類別作預設答案（fallback）。可能碰巧答對，不能一律記為錯誤。

B · MATCHED, NO CONFLICT

候選決策數 = 1

即使命中 5 條規則，只要全都提出 Good，唯一候選仍是 Good；六策略產生相同決策。注意：命中規則條數 ≠ 候選決策種類數。

C · CONFLICT

候選決策數 ≥ 2

至少兩個不同決策同時被命中規則提出。六策略在相同規則集合上各自選出一個答案；原本的衝突仍保留在診斷紀錄。

重要的程式細節：First Match 本身找到第一條匹配規則就返回，所以其回傳的匹配清單只有一條；但研究的 Conflict 指標由事前針對全部規則的獨立匹配診斷取得，不能拿 First Match 的回傳清單判定沒有衝突。
02 · SIX POLICIES

六種方法究竟在改什麼？

方法決策方式無衝突時平票處理
FIRST_MATCH依規則列表順序選第一條命中規則唯一候選類別不計票；改變規則順序可能改變結果
SIMPLE_VOTING每條命中規則給其決策一票唯一候選類別共用最高分平票規則
STANDARD_VOTING加總匹配規則的權重唯一候選類別共用最高分平票規則
GLOBAL_STRENGTHUd / Nd唯一候選類別共用最高分平票規則
POPULATION_STANDARDUd：不重複的支持物件數唯一候選類別共用最高分平票規則
POPULATION_GLOBALUd2 / (Nd Td)唯一候選類別共用最高分平票規則

Ud：支持 d 的不重複訓練物件；Td：各規則正確支持物件數累加（可能重複）；Nd：訓練集中類別 d 的物件數。STANDARD 的權重不可一律視為 Td：集中式使用前件命中訓練物件數，聯邦式目前使用各 Client 的決策一致支持量。

NONE 不是第七種分類法：它只保留候選集合、Coverage、Conflict 等診斷，不產生 Winner，因此 Accuracy、Balanced Accuracy、Macro-F1 未定義。

程式的優先順序

  1. 有且只有一個最高分候選：直接選它。
  2. 最高分或近似最高分平票：如果 default_class（訓練集多數類別）在其中，選 default_class。
  3. 如果 default_class 不在平票集合，按類別名稱的字串排序選第一個。
研究邊界：這是程式定義的決勝規則，不是 LEM2 的數學定理；當 default_class 本身因訓練集類別數相同而沒有唯一多數類別時，其選取由上游的多數類別函式決定，並非這一層另外做了統計最佳化。

First Match 沒有「分數平票」概念；沒有命中規則時，兩者都直接採用預設類別。浮點近似判斷與 NumPy 的 isclose 預設參數對齊（rtol = 1e−5、atol = 1e−8）。

04 · WHO IS IN THE DENOMINATOR?

我們的 Accuracy 不是只計算 Conflict：三類資料都包含在內

N = N0 + N1 + Nc：N0 無命中；N1 有命中但唯一候選；Nc 有兩種以上候選。
Overall Accuracy = (K0 + K1 + Kc) / N：所有測試物件都納入；K 是各組正確預測數。
Conflict-only Accuracy = Kc / Nc：只看衝突子集；如果 Nc = 0，指標未定義，而不是 0%。
Coverage = (N1 + Nc) / N；Conflict Rate = Nc / N。

最重要的實驗解讀：固定同一組規則時，六種策略的 No Match 與單一候選預測相同，因此策略間的 Overall Accuracy 差異來自 Conflict 子集；但不同資料切分、不同 Client 數會改變規則與三個子集大小，不能把不同架構的準確率差異全歸因於平票或 Conflict 策略。
05 · EXPLAIN ERRORS WITHOUT CONFUSING THEM

有 Conflict 不一定錯；沒有 Conflict 也不保證正確

評估階段判斷方式六策略可否從候選中修正？
No Match匹配規則為空；退回 default_class，可能答對或答錯不能；要改善規則覆蓋或改變 fallback 機制
True Not in Candidate有命中規則，但真實標籤不在候選類別集合不能；正解根本不在可選集合內
Wrong Ranking正確標籤在候選內，最後卻選到其他類別可以針對選擇機制改善，尤其是 Conflict 子集
